# 云大学堂 - 布置作业 / 录入题目

## 用途

在课程管理后台的「作业」页新建一份作业，设置基本信息，然后把题目一道道加进去。本 skill 只负责**建草稿 + 录题 + 核对**，默认**保持草稿、不下发**；是否发布、是否下发交用户决定。不上传教学内容、不改章节、不发布课程。

## 前置条件

- 使用 WorkBuddy 内置浏览器（WorkBuddy Browser），通过 `mcp__browser__*` 工具操作。工具未直接可用时先 ToolSearch 加载：`tabs_new` / `tab_goto` / `tab_screenshot` / `cua_click` / `cua_type` / `cua_keypress` / `cua_execute` / `cua_scroll` / `dom_cua_get_visible_dom` / `dom_cua_click` / `tabs_finalize`。
- 用户需已登录云大学堂后台（本会话浏览器通常保留登录态）。跳到统一登录页 `unifiedlogin/#/multiplelogin` 时，提示用户自行登录，不要代填凭据。
- **必须先打开目标课程**：不在目标课程管理页时，先调用 `ynu-course-open-manage` 打开；用户没指明哪门课，同样交给它询问。作业页形如 `#/editcourse/moochomework?id=<课程ID>&type=mooc&courseType=1&sm=1`。

## 关键约束（务必先读）

### 1. 题目来源：用现成原题，不要用 AI 出题

- 用户可能明确要求「不要用 AI 出题」——这是硬约束。此时**绝不能**用平台的「AI 出题 / 智能出题」功能，也不要自己临场编题。
- 正确做法：从用户指定的讲义/题库源里提取原题，**原题干、原选项、原答案、原解析照抄**，一字不改（最多做全角/半角或标点的轻微规范，但要向用户说明）。
- 讲义里的自测题通常形如 `class="quiz-block" data-answer="b"`，含 `.q-stem` 题干、`.quiz-opts` 的 `li[data-opt]` 选项、`.quiz-explain` 解析。写个小脚本正则提取成结构化 JSON（题干 / A B C D / 答案 / 解析）再逐题录入，避免手工复制出错。
- 题目源、范围（哪几讲、哪几道）、题型（单选等）、发布状态、截止时间都要向用户确认，不要替他定。

### 2. 录题入口：从作业编辑页的「添加题目」进入

- 在作业编辑页点「添加题目」→ 选题型（如「单选题」）→ 进入录入表单。
- **不要**绕去试题库独立页 `/exam/#/exam/topicManage`：该页截图容易超限、DOM 常为空，走不通。题目直接加在作业内即可，不必先入库。

### 3. CKEditor 富文本 bug（最重要的坑）

题干、每个选项、解析都是 CKEditor 的 `contenteditable` 编辑区（有的在 iframe 里）。**只用脚本 `cua_type` 填入文字，平台仍判定为空，保存时报「内容不能为空」。**

正确做法——**每个框填完后，用鼠标在该框内再点一下**，触发框架状态更新：

1. 点框内文字行（不是框底边框）→ `cua_type` 输入文字。
2. **再点该框一下**（点文字所在行，别点到空白边缘或下边框）。
3. 逐框重复：题干 + A + B + C + D + 解析，共 6 个框，一个都不能漏。
4. 个别顽固的框：点进去 → `End` → 敲一个空格 → `Backspace` → 再点一下，强制刷新状态。
5. 保存前把 6 个框都补点一遍，再滚到顶部点「保存」。

漏点任何一个框，保存就会失败并提示对应字段为空。这是用户实测确认的平台 bug，不是录入内容的问题。

### 4. 滚动与坐标漂移

- 页面较长，录入时焦点在某个框里时 `Ctrl+Home` 可能无效：先点一下非输入框区域（如右侧空白处）再按，或用 `cua_scroll` 滚轮。
- **滚动后坐标全变**：题单区、选项框会整体位移，选项框还曾被挤到页底边缘（`y≈690` 才是输入区，`y≈730` 点在边框上无效）。**每次滚动后重新截图定位**，不要复用旧坐标。
- 常见可用坐标（1239×968 视口、页面顶部时）：题干框 `x≈700,y≈330`、A `y≈580`、B `y≈725`、C `y≈880`；滚到底部时 D `y≈690`、解析 `y≈880`。**以当次截图为准**。
- 正确答案用选项左侧的 radio 圆圈选，选中后变实心蓝点。

### 5. 敏感词过滤

- 平台对解析文字有敏感词过滤（实测「独立」被拦）。命中时弹确认框，点「确定」即可继续保存，内容会被保留。不要因此删改原题解析；若确需说明，向用户报告。

### 6. 「所属章节」是必填的树形下拉，可能点不中

- 「所属章节」不填则作业无法保存（提示"无所属章节的作业无法在章节内容中显示"）。它是自定义树形下拉：章级（如「1 认识这条链」）+ 展开后的节级（1.1、1.2…）。
- 实测坑：弹层节点在 `dom_cua_get_visible_dom` 快照里**抓不到**；坐标点击选项后下拉收起但值不变（章级、节级都试过）。若反复点不中：
  - 先确认点的是下拉右侧箭头展开，再点目标文字中心；
  - 尝试直接点章级（第1讲作业成功用过章级「1 认识这条链」）；
  - 仍不行时不要反复盲点，停下向用户求助——这是环境/组件问题，硬点只会制造脏数据。
- 离开编辑页用左上角返回箭头，左侧菜单「作业」在编辑态下可能不响应导航。

## 工作流程

### 第 1 步：确认作业方案（向用户，不要猜）

明确四件事：① 哪门课哪几讲/哪几道；② 题型；③ 用不用 AI 出题（默认不用，照抄原题）；④ 发布状态（默认草稿）与截止时间。有讲义源时先解析出结构化题目清单，简述题数与答案分布，再动手。

### 第 2 步：进入「作业」页，新建作业草稿

1. 确认在目标课程管理页，点左侧菜单「作业」。
2. 点「新建作业」，填写：作业名称、所属章节（章级或具体节，按用户要求）、完成方式（个人/小组）、发布时间、截止时间。
3. 先存成草稿，再进编辑页加题。

### 第 3 步：逐题录入

对每一道题：

1. 点「添加题目」→ 选题型 → 进录入表单。
2. 按「关键约定 3」填 6 个框并逐个补点：题干、A、B、C、D、解析。
3. 点选正确答案的 radio（核对变实心）。
4. 6 个框再补点一遍 → 滚到顶部点「保存」。
5. 若提示某字段为空 → 补点对应框再存；命中敏感词 → 点「确定」继续。
6. 截图确认作业题目列表里新增该题，右侧计数（如「单选 (3)」）递增。

### 第 4 步：核对并交付

1. 展开每道题的解析，核对题干/选项/答案/解析与原题一致。
2. 截图核对作业列表：名称、章节、完成方式、截止时间、题目计数。
3. 确认作业状态仍是「草稿」、发布时间「——」、提交 0/0（未下发）。
4. 向用户报告：录入了几道题、答案分布、草稿状态、以及任何偏离原题的地方。
5. 用 `tabs_finalize` 把该标签标记为 `deliverable` 保留。

## 失败处理

- 保存报「内容不能为空」→ 不是没填，是 CKEditor 没认到；把对应框（或全部 6 个框）用鼠标再点一遍，顽固框用「End→空格→Backspace→再点」。
- 文字被插进错乱位置 → 题干/选项框是插入式，清空后在框内点末尾、退格清空再输；实在错乱就取消本题重加。
- 点选项却填进题干框 → 坐标落在框边缘/已滚动，重新截图定位，点在框内文字行。
- 打开试题库独立页异常 → 放弃该路径，回作业编辑页「添加题目」。
- 作业页 URL 打开后标签失控（`tabs_list` 空）→ 用 `tabs_new` 带作业页 URL 重新开一个标签。
- 末尾偶发 500 internal server error → 多为工具层瞬时错误；刷新作业列表核对题目是否其实已保存，齐全则无需重录。
- 用户要求发布 / 下发 / 批量铺到其他讲 → 明确本 skill 默认草稿；确认后再逐项操作，且每次都按本流程核对。
